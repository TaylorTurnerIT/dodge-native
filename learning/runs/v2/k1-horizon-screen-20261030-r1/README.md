# K1 horizon training screen

Two horizon recipes, two independent replicas, 2,359,296 actual gameplay frames per trajectory. Native/PPO/model code is the unchanged pinned runtime; only gamma/lambda differ. The first two real updates qualify each trajectory and remain part of its 36 updates. There is no discarded/repeated qualification, resume, fallback or retry.

`prepare.py --revision N` creates a new registration without models, games, claims or leases. `run_once.py --gate PATH` requires a source review and user authority bound to that exact registration. Run under `/usr/bin/caffeinate -ims`; AC, aggregate RSS, separate MPS and wall limits remain enforced. Parent terminal audit precedes exact lease release. First failure retains evidence and lease.

The copied passive telemetry source is from the 19-test synthetic successor; this campaign validates its actual tensor/return identity and hooks during each counted prefix. This does not claim twin-run trajectory parity. Checkpoints include model/Adam/RNG and episode metadata, but not full simulator state; they are diagnostic endpoints with no automatic resume or promotion. No evaluation games or new cohort opens in this training packet. Outcomes are evaluated only by a later registered packet after strict training acceptance.
