# Existing supervisor binding

Preparation only. `execute_once.py` adapts the retained300 one-use launcher; `observe.py` retains an independent watchdog. The accepted worker, trainer, collector, model, PPO, restore, scheduler and evaluator remain unchanged. `reuse-provenance.json` and `exact-input-diff.patch` identify every reused body and changed line.

The worker creates its registered output. All supervisor logs, dispatch claims and terminal receipts use an owned `dispatch/<run_id>/` directory outside that output. The parent alone finalizes registration, approves every exact `contracts.GATES` entry, spends the exact `progressive1000_parent_spent_launch_marker_v1` marker, and installs the lease. Both processes inherit the marker's identical monotonic `started`; neither grants approval, clears a lease, edits a ledger, retries, selects or promotes.

`worker_cli.py --source-acceptance` expects the **later per-run launch approval**, not the assembly's shared-source acceptance receipt. Envelopes bind those two files separately. `templates/` contains rejected draft envelopes and an inert approval shape, with null gates and start. A parent must bind reviewed code hashes, final registration and launch-approval hashes, the common start, cancel path and control path before invoking the command shape in `launch-command-template.json`. Parent marker fields are exactly `schema`, `registration_sha256`, `run_id`, `started`. No live marker or approval was created here.

Limits remain 1790 work / 1800 total / 10 cleanup seconds; RSS and MPS each 6 GiB; zero retries. Raw-frame cap is `64*13 + 983040*(4+13) = 16712512`; reset cap is one per decision, `983040`. The external observer samples aggregate RSS, worker RSS and MPS separately. It retains raw exits and exact owned group TERM/KILL cleanup. Dependency checks reuse the prior launcher's 13513-file inventory; OS frameworks and driver binaries remain outside that inventory's scope.

Terminal checks cover 60 updates, 983040 decisions, actual optimizer counts, native returned work plus construction/reset costs, five integrity files at 12/24/36/48/60, phase384/cumulative432, scheduler replay from accepted stdlib source, full seed-vector episode identities and separate death/practice-cutoff/cap counts. Failure receipts retain the worker's original failure string and partial optimizer snapshot; missing snapshots or native exceptions without returned results remain unknown. Integrity files are hashed, never deserialized. Embedded checkpoint identities, counters, LR, full vector and eligibility still require the parent terminal audit before acceptance. Formal comparison remains separate.

Run bounded controls with `python3 -B tests/run_controls.py` from this directory. `test-receipt.json` records synthetic evidence only. Historical retained324 same-parent restore/resource metadata is linked in `historical-evidence.json`; it does not qualify changed successor origins, reseeding or cutoff behavior. No standalone restore probe is required or run. `gate-evidence-map.json` records remaining parent decisions and missing real qualification honestly.
