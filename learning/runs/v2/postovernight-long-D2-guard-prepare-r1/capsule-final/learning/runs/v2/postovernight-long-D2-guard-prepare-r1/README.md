# Guard repair and controlled D2 r2 preparation

Preparation only. No campaign, training, inference, ML/native import, checkpoint deserialization, active lease, scheduler, commit, PR, deployment or delegation is performed. Parent must reconcile fresh frozen review before any separately owned launch. A failed contention stress blocks launch and requires a fresh substantive design; it must never trigger a retry here.

The controller derives from the exact R4 controller/executor. Only registration constants, Guard admission/timing, verification timing wrappers, primary-failure reporting, and telemetry output supervision change. Nonforced full verification starts at 2 seconds. The independent monitor and conservative previous-successful-start to current-pass-end limit remain strictly 5 seconds. Full pins, readonly capsule walks, legacy frozen rebuild and module-origin/mirror checks remain. Forced update/evaluation checks, learner, Schedule and run_schedule stay byte-identical. All 9,870 R4 full pins and the older 9,675 union remain exact. The unchanged 75 legacy sources and origin policy retain their historical hashes.

Each admitted pass records trigger/start/end, duration, forced/background/thread identity, trigger delay, verify-lock wait, per-component wall/CPU duration, thread CPU time, conservative full gap and completed controller hash files/bytes. Legacy validator internal file_hash calls use their unchanged implementation and are explicitly excluded from the controller hash byte counter. They remain timed within legacy_frozen_rebuild and fully execute in production. Rows remain in bounded memory, with no telemetry writer thread or IO in the independent resource monitor. Main-thread timing persistence requires owned Guard thread absence, checks permission/deadline before creation and every write, and remains under the existing process lifetime/cleanup bounds. Abrupt process death can lose unflushed rows; failure/interrupted rows survive to the extent safe teardown permits.

Worker timing JSONL and its hash manifest are ordinary campaign outputs, included by the campaign artifact manifest and outer fixed-output allowlist. Inner/outer timing JSONL and hash manifests are separate execution-directory evidence, written after their final full pass and owned Guard teardown; they are not inserted into the already-closed campaign manifest. These external timing manifests must be independently inventoried by the parent, alongside the outer raw exit/wall. A failure during final timing IO still rejects via raw failure or missing evidence; no receipt alone proves success.

Primary failure is latched before ACK/cleanup notification. Later TERM/cancellation is secondary when another failure already owns outcome/error. A prior independent Guard failure is preferred only if it predates the first recorded signal; a user cancellation first remains cancelled and rejected. ACK permission and earliest shared cleanup deadlines are preserved.

Validation executes stdlib only. Every attempt keeps sources, commands, raw exit/wall/log and partial evidence. System-Python annotation incompatibility, inherited stub repair and the actual worker overwrite regression are retained separately with explicit correction notes. No historical counts transfer. The continuous-Python contention stress is exactly one attempt over the new frozen pins and actual worker verify closure. Its unchanged legacy IO bodies use disclosed static ML metadata/native lookup substitutes, never ML/native execution. It stops on the first Guard failure. Finite timing samples do not establish production runtime or population tail guarantees.
