# Longer D2 controller: read-only API feasibility audit

A new standalone controller is feasible without changing any of the 75 frozen package/core/learner inputs. The existing overnight CLI cannot honestly authorize the new two-hour experiment. Its configuration and authority checks must remain unchanged.

This audit inspected source and JSON, extracted signatures with the standard-library AST parser, verified all 75 current source hashes, and checked the pinned successful D1 checkpoint/terminal/proof bytes. It did not import Torch or project modules, deserialize checkpoints, run tests, construct environments, evaluate policies, or train. Serialized tensor/optimizer/RNG equality remains a required implementation/runtime check.

## Concrete legacy coupling

- `identity.validate_config(config)` at line 88 requires full equality with `default_config(...)`. The registered D2 row fixes both the old run seed and 1,800-second budget. New seed or 7,200 seconds fails deliberately.
- `identity.build_identity(...)` at 151, `check_frozen(...)` at 181 and `training_env_config(...)` at 191 all invoke that legacy validation. They cannot validate the actual longer-run configuration unchanged.
- `checkpoints.validate_transition(...)` at 216 also validates both full legacy configs after comparing source/runtime/model/reward/gate identities. Passing a new longer-run identity to it fails. Do not strip fields, monkeypatch defaults, catch this rejection, or mislabel its old target as the actual new experiment.
- `train_teacher.Experiment.__init__` at 132 invokes legacy lease validation and `validate_transition` twice, then `make_environment` invokes `training_env_config`. Instantiating the class is unsuitable. Calling its methods on an object fabricated with `__new__` would bypass that constructor authority; avoid it.
- `train_teacher._run_worker` at 427 validates the old config and explicitly checks the expired cutoff at 442. `_run_supervised` at 502 calls the old `check_budget`. `supervision.check_budget` at 93 rejects budgets above 1,800; `Guard.check` at 156 rejects current time after 13:00 UTC. None should be patched or ignored.

| --- | --- |
| `checkpoints.validate_terminal_receipt(run_dir: Path, anchor: dict) -> tuple[dict, dict]` (149) | Validates the immutable historical D1 terminal chain against an exact eight-field parent anchor. Requires parent-observed supervisor exit 0, source run/worker passed, no retries/relaxation/B/E, matching identity/config/certificate/checkpoint and manifest hashes. It validates the old D1 config, which remains valid; it does not check the current wall-clock cutoff. This establishes historical source success, not new-run authority. |
| `checkpoints.load_checkpoint(path, expected_identity=None, expected_sha256=None)` (112) | Hash-pinned CPU load and checkpoint/identity integrity checks. It uses `weights_only=False`; if a new reader instead uses `weights_only=True`, retain the reviewed narrow NumPy allowlist and equivalent structural checks. Only the exact accepted D1 file is a permissible training parent. |
| `checkpoints.require_complete_update(state)` (129) | Rejects `interrupted_mid_update`, `in_update`, or explicitly incomplete progress. | `checkpoints.restore_learner(state, model, optimizer, device="cpu")` (138) | Strict model state load, optimizer state load and `restore_rng`. No configuration or lease validation occurs here; call only after the new controller's complete source/authority checks. |
| `checkpoints.capture_rng(device="cpu", numpy_generator=None)` / `restore_rng(state, device="cpu", numpy_generator=None)` (22/31) | Python, global NumPy, optional owned NumPy generator, CPU Torch and MPS Torch state; requires matching `torch_global_<device>` backend. | `train_teacher.make_optimizer(model, config)` (74) | Constructs Adam with the exact `PPOConfig` learning rate and epsilon. No legacy full-config validation. Construct optimizer before restoring the parent optimizer and RNG. |

It can validate a separately validated new config whose relevant environment fields are unchanged apart from the explicit new run seed. |

Returns observations for the next collection; persist them and keep the live environments. |
| `ppo.ppo_update(model, optimizer, batch, config, *, check_guard=None, progress=None)` (403) | Unchanged GAE and optimization. Sets progress incomplete before validation, increments actual partial optimizer steps, and only marks `complete=True` on successful return. Increment complete-update counters only after it returns. Nonfinite losses/gradients are already rejected. |
| `train_teacher.require_raw_diagnostics(batch)` (79) | Confirms the four mandatory raw reward/frame arrays exist. No legacy authority coupling. |
| `dev_eval.evaluate(model, stage, device="cpu", *, check_guard=None, env_factory=None, episode_stream=None)` (63) | Original fixed 64 D seeds, deterministic argmax, original independent B1/batched-alive layout. | `dev_eval.progress_passed(phase, evaluations)` / `validate_summary(result)` (135/151) | Recomputes row-derived summaries and preserves D2 score ≥50 and alive ≥3,060. No custom threshold or action mode is needed. |

## Smallest explicit new contract

1. Freeze a new post-overnight protocol with 7,200 seconds, a distinct run ID and training run seed, exact D1 terminal anchor/checkpoint, the original learner configuration, original 75 source hashes/runtime/native binary identities, all guard limits, evaluation cadence and stop rules. Give the standalone helper/tests their own source inventory and hash. Do not put new code/tests inside the inventoried package/core directories.
2. Use a new authority/identity envelope rather than claiming the legacy M3 registration changed. Separate the unchanged learner contract from the new controller/config/budget/seed/parent-anchor contract; hash-bind both. Validate exact key sets and exact declared deviations. Preserve actual imported capsule paths separately from the historical identity's original paths. Calling legacy `build_identity` against a copied capsule can also change the recorded extension path and require M2 receipt files outside the 75 source set.
3. Reuse the unchanged D1 terminal verifier, then explicitly complete source-parent checks from `validate_transition`: terminal filename/hash, candidate tag, complete update, phase D1, identity/config equality with the source run, D1 progress proof, and exact unchanged learner/source/runtime/model/reward/gate contract. Reject every failed D2, partial, probe or nonterminal parent. A separate reviewed validator must authorize the new controller/budget/seed; an old successful transition check is not that authority.
4. Restore the D1 model, Adam and RNG after constructing the model/optimizer. Independently verify entry model/Adam/RNG equality on CPU representations. Inherit absolute counters and checkpoint index, reset only `phase_updates` to zero, and record explicit phase-origin counters. Start 64 fresh environments with initial episode indices zero in the new seed namespace. Log abandoned parent episodes once; never restore their environments or partial rollouts.
5. Construct the new environment kwargs directly from the new exact validated protocol because `training_env_config` is legacy-coupled. Then reuse `verify_training_env`, `TrainingEnvLog`, `collect_rollout`, `ppo_update` and original evaluation/gate functions. Reproduce the old update bookkeeping explicitly rather than bypassing `Experiment.__init__`: complete update counters after success, partial Adam progress separately, native completions before collection acceptance, and no live reset at checkpoint/evaluation boundaries.
6. Keep sampled RSS/self-peak and MPS guards separate, a parent-owned monotonic deadline anchored once at supervisor launch, and owned worker cleanup. The new lease must bind the exact new protocol/controller/identity and unchanged D1 source anchor. No same-phase resume, checkpoint-local budget restoration, retries or failed-run parent promotion.
7. On failure during an update, retain an `interrupted_mid_update` diagnostic checkpoint with exact partial progress. On a clean budget endpoint below the existing progress gate, record that distinction without a passing curriculum certificate. A gate pass still requires a successful exact terminal receipt and parent acceptance. New result identities should not accidentally satisfy old transition validators; old config validation should continue rejecting them. No automatic D3/B/E work follows.

## Bookkeeping details worth preserving

- D1 contributes 48 absolute complete updates and 6,144 Adam steps. D2 phase updates begin at zero. Do not count inherited work as new D2 experience.
- Keep explicit phase-origin decision/raw-frame counters because the inherited absolute counters otherwise reproduce the earlier mixed-experience reporting error.
- `checkpoint_resume_boundary` records describe what a future resume would drop; `make_state` does not reset the currently live environment.
- Checkpoints consume and record their own publication time. Reserve enough of the fixed budget for final checkpoint/evaluation/verification; do not let that reserve become additional training time.
- `collect_rollout` may have accepted completed native episodes before a later collection/update failure. Preserve those valid episode audits separately from complete-optimizer-update totals.
- Keep the inherited three-consecutive-KL>0.1 stop and finite diagnostics in any explicitly reproduced controller bookkeeping. The old D1-competence-dependent entropy rule must not be silently reinterpreted for a successful D1 parent.

No implementation blocker requires changing the model, PPO, native environment or the old guards. The necessary work is the new, reviewed controller authority and its narrow parent/identity adapter.
