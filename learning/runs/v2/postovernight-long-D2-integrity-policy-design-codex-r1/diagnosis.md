# D2 integrity policy redesign — Codex fallback r1

Status: design only, not implemented or accepted. The parent must reconcile this proposal, freeze the implementation and a new protocol, and reconcile a fresh review before consuming the unused r2 experiment authorization. This task performed source/receipt reads and stdlib hashing only. It did not execute the candidate, import ML/native modules, deserialize checkpoints, run a stress or rehearsal, launch children, or change source, protocols, parent state, leases, or scheduler settings.

## Recommendation

Replace the five-second full-tree watchdog with **verification at declared execution boundaries, plus full provenance verification before launch and before acceptance**. Keep the original legacy import paths for this experiment, an explicit parent-owned no-writer reservation, and the readonly controller capsule. Retain faithful `check_frozen` and module-origin checks at the existing forced worker boundaries. Remove periodic integrity hashing from all three roles. Resource, lease, cancellation, ownership, and absolute deadline monitoring remain independent and unchanged in their limits.

This deliberately gives up a five-second revisit claim. It is a different, narrower guarantee appropriate to a controlled local experiment: observed input equality at declared boundaries, a real unchanged legacy identity reconstruction, exact D1 restoration and entry behavior, and full archival/provenance equality at the two ends. It is not continuous immutability or resistance to a malicious process running as the same user. Do not describe it as equally strong polling with lower overhead.

Do not relocate the legacy package merely to call the execution immutable. The existing path-sensitive identity and historical transition proof make relocation substantially more work than this run needs. A truly isolated active-input capsule is a reasonable later improvement, but it must have its own identity and explicit historical-to-current binding. A chmod on files owned by the same user does not supply that isolation.

## What integrity actually means here

1. **Accidental concurrent edits.** A cooperating parent can reserve the workspace, Python installation, environment, and input paths against edits, builds, package installs, cache rewriting, and other agents. Check persistent mutations at the next declared boundary and at postflight. The reservation is an operational assumption supported by job ownership records, not an OS proof that arbitrary writers cannot exist. If the parent cannot secure that reservation, do not claim it: postpone launch or use an explicitly isolated new execution identity.
2. **Malicious same-user/process writes.** The current verifier, expected hash data, interpreter, memory, and outputs share the user's authority. That actor can change protections, replace files between reads, monkeypatch functions, or fabricate receipts. Five-second hashing does not solve this threat. Neither does this proposal. A different UID, enforced readonly mount/snapshot, or stronger isolation would be a separate architecture and is unnecessary for the stated local baseline.
3. **Transient edit then revert.** Old polling can miss a change entirely between reads; a whole-tree pass is not an atomic snapshot either. New boundary-only checks have larger blind intervals and can miss changes that old polling might have caught. Admit this explicitly. Under either policy, an offending version may execute before the next check. A detected mutation invalidates the whole run, including earlier checkpoints; do not infer a clean prefix from detection time.
4. **Loaded code versus files.** A Python function already loaded into memory does not change when its `.py` file changes; a hash of that path is not a hash of executing bytecode. Conversely, a modified lazy import or later data read can affect execution. Validate the loaded project module paths, package search paths, file bytes, and mirrors at boundaries, and include every source/data path that can be read later. No arbitrary dynamic project imports, `reload`, `exec` from disk, or new unregistered data inputs are allowed. Unexpected loaded project origins reject at the next boundary; this does not promise prevention of their first execution.
5. **Bytecode caches.** `-B` prevents writing `.pyc`; it does not disable reading existing caches. Do not claim source hashing alone proves the source was loaded. For the new launch, register a fresh empty `PYTHONPYCACHEPREFIX` under the new execution-owned directory and keep `-B` / `PYTHONDONTWRITEBYTECODE=1`. All three process roles inherit it from interpreter startup. Assert the prefix is canonical, contains no cache files, and matches `sys.pycache_prefix`; verify again at boundaries/finalization. Do not delete or chmod original caches. This avoids existing project cache reuse without import hooks or editing package sources. It is a small explicit startup-policy change requiring rehearsal and review, not retrospective proof about old runs.
6. **Archival drift.** Old review fixtures, test logs, preparation scripts, and old capsules are provenance, not repeatedly consumed learner inputs. Preserve their complete path/hash declarations and explicitly verify each declared archive binding at preflight and postflight. A manifest hash by itself does not verify its member bytes. Failure or missing member prevents acceptance. No continuous archival drift claim survives this change.
7. **Mutable parent state.** Check only the exact parent-owned `active_long_campaign` lease and cancellation field at the existing at-most-0.5-second cadence. Do not hash the entire state document as immutable. Other parent bookkeeping may change. Malformed JSON, missing lease, lease mismatch, or cancellation remains a failure.
8. **Outputs.** Hashes/manifests prove bounded consistency at observation times, not trustworthy authorship against the same user. Require the actual checkpoint/evaluation bindings, observed raw exits, finite wall time, reaping and positive group absence, stable writers, and parent-held final receipt hash. Postflight integrity failure or lost mandatory evidence rejects even if the learning gate passed. Later drift invalidates later use unless the pinned artifacts are recovered unchanged.

The old `end_current - start_previous <= 5` check conservatively bounded revisit intervals only for completed successful passes, with a separate staleness latch. It did not prove a write-free interval, atomic file-set consistency, code-memory equality, causality of a failed run, secure output ownership, or numerical reproducibility on MPS. A latency deadline is not reproducibility.

**A — archives.** Everything else in the historical full-pin closure, including previous harness sources, reviews, stress artifacts, and evidence fixtures not read by the current run. This preserves identity correctness at observations, with a controlled-writer assumption between them. It does not offer a fixed maximum source mutation detection latency. Boundary duration, bytes, and actual intervals are reported, not gated at five seconds. Hash IO remains subject to the existing absolute experiment/finalization deadlines and responsive resource/cancellation monitors.

## Why keep the original execution paths for this D2

`python/dodge_rl/identity.py:181–188` reads the frozen identity, rebuilds it from the real runtime, compares the entire object, then rehashes the identity. Its rebuild inventories sources, validates fixed protocol/gate/contracts, verifies accepted native/build artifacts and the actual extension origin, and records interpreter/Torch/NumPy/MPS metadata. This is not replaceable with worker-supplied fixture metadata.

`checkpoints.py:216–265` independently validates the D1 terminal receipt, anchors the exact checkpoint, loads it, compares source/runtime/architecture/reward/gate identity, validates registered configs, and enforces a passing complete parent. Keep those validators unchanged and call them on the original root/base D2 identity as historical proof. Then the separately registered long config/identity authorizes this new run. Never pass the long config through an old validator that cannot accept it, remove mismatching fields, monkeypatch defaults, or rewrite historical paths.

A new active capsule could execute copied Python/native files under a new identity while retaining original-path historical validation. Doing this faithfully requires a deliberate mapping between historical D1 identity and new execution origins, re-evidencing native/dependency loading, and review of dual-path behavior. It could improve prevention of accidental original-checkout edits only if actual execution reads exclusively from protected copies. The current capsule does not provide that guarantee. For one sound D2 baseline, retain original paths with an explicit no-writer reservation and boundary verification. No original checkout chmod is proposed. If hard prevention becomes required, choose the new capsule architecture explicitly; do not pretend the reservation meets that stronger requirement.

## Failure, cancellation, and reporting repair

Use the existing `FailurePool`, latch, and failure/ACK channel. Add only a compact first-failure descriptor: timestamp, kind, outcome, role, timing basis, and signal number where relevant. Keep the first local descriptor for audit and reconcile the global minimum as earlier peer evidence arrives. A locally latched outcome must not block a genuinely earlier ACK-provided event from becoming globally primary. Existing rejection remains sticky; no earlier/later event can restore success.

Separate `first_cancel_at`/signal from `first_alarm_at`. DEFER delays raising, not recording. The fixture cancel at 1 then guard failure at 2 must report cancellation primary even when the caught argument is the guard exception. The inverse reports guard primary. Record an independently delivered first SIGINT/SIGTERM as cancellation, sender unknown. A signal observed after an already established earlier failure is secondary cleanup-phase evidence; record the executor's forwarding action before sending. Do not infer a user sender. If an earlier peer failure arrives late, reconcile that ordering too. Pending signals discovered by the finite scan have observation timestamps, not invented kernel-arrival timestamps.

Guard/source detection uses its detection timestamp; a normal generic exception uses first-caught/observed time unless its source explicitly supplies a reliable timestamp. `Stop` construction alone does not establish failure occurrence. Registered deadline crossings may use the known absolute cutoff, labelled as such. Equal timestamps use a documented deterministic tie rule (kind/role/local sequence), explicitly no claim of physical ordering below clock resolution. Compare clocks only within the registered interpreter/shared-clock handoff contract; never subtract unrelated preparation-interpreter epochs.

For every accepted peer failure, update `first = min(first, peer_first)` and `until = min(until, first+10, T0+7210)`. A late earlier event may leave no cleanup time; stop rather than reset. Propagate the descriptor along the existing ACKs, preserving failed-ACK write prohibitions. Keep raw parent wait statuses, wall observation, owned-process groups, one timer arm, failure watchdog takeover, and finite final exit unchanged.

Repair telemetry narrowly: after failure is latched and failed-worker write permission/ACK is established, attempt the authoritative failed receipt **before** optional timing persistence. Use independent error handling for receipt and telemetry, with the failure pool's deadline-aware IO permission. Never retry an already-created exclusive timing path as a precondition for failure evidence. Disable the normal-phase hash observer for optional failure telemetry or use an explicitly failure-deadline observer; it may not consult expired normal authority. Missing/partial timing is reported as lost diagnostics and cannot prevent the failure receipt attempt. Mandatory integrity verdict/first-failure metadata belongs in the receipt, not only in timing output. Filesystem failure can still prevent any receipt: raw exit/wall then reject; never claim a universal durable-write guarantee.

On success, complete mandatory integrity/output verification before the final accepted receipt. Diagnostic timing is optional in normal and failure paths. A normal timing-write error records diagnostic loss and continues mandatory publication; it does not itself invalidate a sound integrity verdict. If timing files exist, inventory their actual bytes with a complete/partial status; a partial timing file is opaque diagnostic evidence, not a passing verification log. A changed declared diagnostic hash still rejects output consistency. Keep inner/outer timing outside the closed campaign inventory and separately inventory any such execution outputs for the parent. Remove timing files from the mandatory acceptance set, retain a required compact integrity-boundary summary, and disclose the output-schema change in the new protocol. If later finalization fails, replace the receipt with `accepted:false` before any diagnostic work. A stale accepted receipt plus raw exit 1, missing exit, late exit, missing postflight, unknown writers, or mismatch remains rejected by the exact parent consumer. Preserve `accept_observed`'s raw-exit requirement; add the new mandatory integrity/protocol fields rather than trusting a generic manifest.
