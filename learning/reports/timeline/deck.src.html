LucasHow it works

velocity-flow-v2: a learned danger map

The network never picks a move. It draws where danger will be; fixed arithmetic turns that map into a move.

Observation

One frame on a 32×32 grid of 4px cells.

11 channels: 8 object types, player, x and y velocity

+ 10 numbers: player position, velocity, nearest-threat geometry

→

Conv trunk

3×3 conv at 32×32, then three at 16×16, one dilated to reach across the arena. A 4×4 pooled summary is blended back so every cell sees the whole arena.

11 → 32 → 64 → 64 → 32 channels · ~80k weights

→

Danger field

A 1×1 conv gives six danger maps, one per moment in the future.

+4, 12, 24, 48, 72, 108 frames

↓
↓

Because the output is a picture, the field can be drawn behind the game while you watch it play.

Critic

Trunk channel means, an 8×4×4 coarse map of the arena, and the player numbers go into a small MLP.

32 + 128 + 10 → 64 → 64 → value

Controller

For each of the 9 moves, look up where it takes the player at each future frame and read that frame's map there. Sum the readings, then standardise across moves.

× learned sharpness → 9 action logits

Learned weightsFixed rulePPO, γ 0.997, one decision per frame
Lineage: MLP → hybrid CNN (87% of its weights in one flatten layer, which also died) → field-cnn (fully convolutional field) → VelocityFlow (velocity raster instead of a frame stack) → v2 (critic gets a coarse map; trunk middle at 16×16 for speed).

A one-step look ahead with straight-line guesses. Every step is a fixed rule; nothing is learned.

9 moves

Neutral, 4 directions, 4 diagonals.

→

Player path

Run the game's own movement model (inertia, speed cap, walls) for each move.

12 frames

→

Threat boxes

Extrapolate every lethal box in a straight line from its observed motion.

12 frames

→

Rank

  • A safely reachable powerup wins

The entity-transformer teacher

Instead of a picture, it sees a list of objects, and attention lets each object weigh the others.

Global token

Player position, velocity and size, game speed, score, distances to walls.

14 features

+

Entity slots

Each enemy, blast, powerup and pattern box: position, motion, signed gaps to the player, hazard timing. A type ID says what it is; a mask marks empty slots.

80 slots × 16 features · 8 types

→

Transformer

Every token embedded to width 128, then two attention layers.

2 layers · 4 heads · feed-forward 256

↓

No pixels, no future spawns, no hidden timers. The plan was to distill it later into a student that sees only the screen.

PPO on 64 games × 256 steps per update. Reward: score change + 0.01 per frame alive, −5 on death.

Heads

An actor head gives the move; a critic head estimates future reward.

SpaceBot: stay where there is room

Simulate every threat with its real steering rule, then go where you can get to before anything else can.

9 plans

Each move held for 24 frames.

every frame

→

Simulate

The player exactly. Each enemy with its real rule: homing, friction, wall bounces, kamikaze slow-down. Blasts grow; pattern boxes are extrapolated.

→

Reject

Drop every plan that collides with anything.

→

Room map

On a 12×12 grid, how much sooner the player reaches each cell than any threat. Sum it, plus 0.3 × nearest clearance.

threats 60 frames out · capped at 30

→

Adjust

  • Powerups: explode 2.0, freeze 0.8, shrink 0.5
  • Pull toward safe powerups
  • Penalty for ending in a sweeping bar's path
  • Leave the centre before the anti-camping guard
Every step is a fixed rule; nothing is learnedSees exact current state, not future spawnsNo pattern-specific knowledge, no randomness
Built Nov 4 alongside a Python port of Taylor's M0 (with Taylor's OK); powerups added Nov 5. Both can be watched in the dashboard with their own overlays.

TaylorHow it works

The belief planner: M0 plus imagined futures

Try each move in a copy of the game, let M0 play on in several possible futures, and keep the move that survives longest on average.

9 root moves

Each one tried in a clone of the current game.

→

Resample futures

4 guesses at what spawns next, built from present and past state, not the real random seed.

4 futures per move

→

M0 plays on

Each branch continues under M0 with its own copy of M0's memory.

up to 192 frames

→

Score

Alive frames + 0.001 × score change, −1,000 on death.

→

Choose

Highest expected value wins; exact ties go to M0's own choice.

~39 ms per decision

Every step is a fixed rule; nothing is learnedThe future is approximated, so it is not fully clairvoyantIt overrode M0 on under 1% of decisions
Overrides were rare (0.15–0.80% of decisions), but those few choices more than doubled survival on every difficulty. The same code can also score leaves with a learned value estimate.

dodge-danger: Lookahead and Landscape

Two hand-built danger potentials. Lookahead is exact but cheats; Landscape is a cheap hand-shaped hill for the player to roll down.

Lookahead · ceiling, sees future spawns

Clone the game

An exact copy, random state included.

→

Heat field

Roll every enemy forward under its homing rule; record the first frame a still player at each cell would be hit.

horizon 36 frames

→

Search

Receding-horizon search over the 9 moves using exact clones.

Landscape · fair, from current state

Particle

The player as a damped particle: position q, momentum p.

H = ½‖p‖² + V(q)

→

Potential V

Gaussian tubes along each enemy's predicted path, ridges at lethal boxes and walls, fixed corner and centre terms, a slight tilt to break symmetry.

→

Roll downhill

Steer along −∇V.

hand-set A, w, σ per kind

Nothing is learned yetThe hand-set parameters in V are what a learned Hamiltonian network would replace
Lookahead's heat field is also meant as ground truth for fitting a learned residual potential. That is where SpaceBot data could come in.

AppendixHow the live slides work

The deck runs the real engine

dodge-core, the binding's VelocityFlow encoder and slot state, and Taylor's dodge-danger compile to one wasm32 module with SIMD: 772 KB including the CNN's weights, no imports, no JavaScript glue. The page reads the screen, stats and each policy's internals straight out of linear memory.

Python bots were ported, not approximated, and each port was checked against its original before it went on a slide. So was the danger-field renderer: dodge/display.py's set_field and compose, in numpy's float32 arithmetic with its pairwise sum, match the Python window on all 9.8 M colour values of 200 test fields.
